# 02 · 方法论：为什么本仓库的结论可信，以及常见陷阱

这份文档记录的是**测量方法**，不是结论。本项目的多数弯路都来自测量，而不是来自优化想法。

## 1. 唯一权威指标

| 指标 | 来源 | 说明 |
|---|---|---|
| `prefill_ms` | `ab-*.log` 的 JSON 尾段 | **首选**。服务端自报的单次 prefill 墙钟时间 |
| `GPU timeline NNNNN ms` | `<tag>.log` | 引擎内部 GPU 时间线汇总，与 `prefill_ms` 相差 ~0.1% |
| `prefill_tps` | 派生 | `input_tokens / prefill_ms × 1000` |

`gpu_busy_prefill_mean_pct` 长期在 **99.2~99.5%**，`mem_busy` 仅 ~22% —— 说明这是**纯算力受限**，不是带宽受限，也不是排队问题。这个事实贯穿全部优化判断。

## 2. 控制组会漂移（最容易骗人的一点）

同一份配置、同一台机器、同一个 chunk：

```
2026-10-22 02:11   gsol-c1 (控制组)   prefill_ms = 61,208.9
2026-10-22 02:17   gsol-c2 (控制组)   prefill_ms = 61,333.7
2026-10-22 03:45   sm-c1   (控制组)   prefill_ms = 60,315.4   <-- 同配置，低 1.5%
2026-10-22 03:50   sm-c2   (控制组)   prefill_ms = 60,244.1
```

**40 分钟内控制组自己快了 1.5%。** 单看"实验组 vs 更早的控制组"会得到虚假收益。

因此本仓库的硬性规则：**任何 < 1.5% 的收益，必须在同一时间窗内用 `c1 / n1 / c2 / n2` 交替执行**（见 `bench/ab_pin4.sh`），并且要求

```
Δ% = ( meas_n − meas_c ) / meas_c × 100
其中 meas_c = (c1 + c2) / 2,  meas_n = (n1 + n2) / 2
```

并且要求 `|c1 − c2| / meas_c < 0.5%`，否则该轮作废重跑。

## 3. 独立微基准不是有效仪器

这是本项目最反直觉的一条。同一个 `rocblas_gemm_ex` 调用（N=2560, K=6144）：

| 测量方式 | 时间 | TF/s |
|---|---|---|
| 独立 microbench（遍历全部 512 个 solution） | 13.357 ms | **72.07** |
| 独立 microbench（默认 solution） | 20.206 ms | 47.64 |
| **引擎内实测** | **10.334 ms** | **95.6** |

引擎内比任何独立配置都快 —— 说明微基准没有还原真实的流/预热/缓存状态。**结论：微基准只能证伪方向，不能证明收益；一切收益必须在引擎内 A/B。**

## 4. 可迁移性判据

> **可迁移**：同一个 rocBLAS kernel，仅换 Tensile solution（换 tile 参数会生成不同 kernel → 不可迁移）。
> **不可迁移**：换 kernel、换 tile 尺寸、换数据通路。

统计结果：跨 9 个形状的 solution 扫描中，**只有 2 个**能迁移到引擎内产生收益。

## 5. 归因工具

没有 rocprof / omniperf（该环境不提供）。全部归因依赖两个自有开关：

| 开关 | 作用 |
|---|---|
| `STRATA_PREFILL_TIMING=1` | 打印分阶段耗时（gate/up、qsa attn、gdn、hc read …） |
| `STRATA_GEMM_ATTR=1` | 打印每次 GEMM 的 (N, K, ms, calls)，用于把阶段耗时拆到具体形状 |

`STRATA_GEMM_ATTR` 实测输出样例（2944 次调用，合计 21,244 ms）：四个主导形状占 **89.7%**，其中 dequant 只占 **1.8%** —— 这一条直接否决了"缓存 dequant 结果"的想法。

## 6. 实验纪律

- 实验只在**专用卡**上做，用 `LEASE.json` + `flock` 双重互斥；脚本 `exec 9>lock; flock -n 9 || exit 7`
- 每个实验必须有**同一批次的控制组**，否则不予采信
- 失败实验**不删除**，写入 `docs/04-closed-paths.md`，这是本仓库最有价值的资产
- 补丁必须 **fail-closed**（锚点找不到就报错退出，而不是静默跳过）
